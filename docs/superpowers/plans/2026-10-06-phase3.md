# Phase 3 — Face landmark detection implementation plan

> **For agentic workers:** Use the executing-plans workflow; shared interfaces below are fixed. Run regression/smoke verification once after integration, not in parallel worker slices.

**Goal:** Implement Phase 3 of `16_Development_Roadmap.md`, then assess readiness against existing docs without claiming missing dataset/hardware evidence.

**Architecture:** `VideoReader` owns sequential OpenCV capture, validates source time and performs timestamp-grid sampling. `FaceLandmarkDetector` owns one MediaPipe Tasks VIDEO session per source. Preview CLI composes them, draws normalized landmarks on an unmirrored copy, and records aggregate run evidence without saving faces by default.

**Tech Stack:** Existing Python 3.12 virtual environment, OpenCV contrib, MediaPipe Tasks, NumPy; no additional dependencies.

## Global constraints
- Preserve FramePacket and LandmarkResult signatures. No fabricated landmark confidence or visibility.
- Offline timestamps prefer CAP_PROP_POS_MSEC, strictly increasing before and after integer-ms conversion. Fallback frame_index/fps requires caller's explicit constant-FPS verification, is recorded, and still must be increasing.
- File FPS/frame count/duration must be finite/positive; compare source timestamp against duration with one-frame tolerance. Decode failure before declared end is an error, not silent EOF.
- At most one emitted source frame per target timestamp bucket; target_fps finite in (0,20]. Timestamp jitter reflects source cadence, not synthetic duplicates. Every source frame is decoded sequentially, with no seek-per-frame.
- Webcam uses monotonic capture-time timestamps, releases on failed read and reports ERROR. Physical disconnect and face/no-face observations must not be claimed from synthetic tests.
- Missing face means points=None and face_detected=False. Malformed points must never become valid features.
- Phase 3 does not implement Phase 4+ quality gates, EAR/MAR, training or CameraWorker.
